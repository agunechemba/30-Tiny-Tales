Chapter 6

The Toolbox and the Translator

Editors, Compilers, Interpreters

🧰

A programmer's workbench is full of tools. The first is the editor — a simple word processor where you type your source code and save it as a text file. No fancy fonts, no underlining — just characters.

The second tool is the translator, and there are three kinds. A compiler reads your entire program, converts it all into machine language, and saves the result in a separate file — often called an EXE. Do it once and you're done. An interpreter translates your program one line at a time and stores the result in memory. Every time you run the program, it must translate again. A p-code compiler is a hybrid: it translates your code into an intermediate form (byte code), and a special run-time program finishes the translation on each machine. Java is the most famous user of p-code.

The third tool is the debugger. It lets you step through your program line by line, set breakpoints to pause in specific places, and watch your variables change values. Without a debugger, finding bugs is like searching for a needle in a haystack.

Most compilers bundle editor, compiler, and debugger into one program called an IDE (integrated development environment). When your program is ready, you add two more tools: a Help-file creator (so users can find help on-screen) and an installation program (so users can copy your program to their computer without manual errors).

Big Idea

A programmer needs an editor to write, a compiler or interpreter to translate, and a debugger to fix. A compiler translates the whole program once; an interpreter translates one line at a time; p-code is a hybrid. An IDE combines all three.

Try It!

Imagine translating a whole book at once (compiler) versus translating a speech sentence by sentence live (interpreter). Which would be faster to read afterward? Which would be faster to start? Which would you prefer for a big project?
